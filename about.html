What openpathogen is and how it works

Developed by Amulya Baral

openpathogen is an open-source tool that finds antimicrobial resistance and virulence genes in sequencing reads. It runs entirely in the browser.

It uses KMA 1.5.1 for read mapping and fastp 0.22 for quality control. Both are compiled from source to WebAssembly.

Your data is analysed on your own computer and is never uploaded. This makes it safe to use with clinical or unpublished data.

There is no account and no server. The only downloads are the app, the WebAssembly engines and the databases. The privacy section lists every request.

Databases are downloaded once, checked against pinned SHA-256 hashes and cached in the browser. Repeat runs start at once. The first run against a large database waits for the download.

Privacy: what leaves your browser

Nothing you upload leaves your machine. A website still makes some network requests. This is the full list, so you can check it against the source code or your browser's network inspector.

Your sequencing files (FASTQ)
Never uploaded and never written to disk. Files are read into memory, processed by WebAssembly and gone when you close the tab. No cookies and no accounts.
Page views (Cloudflare, the host)
The site is served by Cloudflare, which sees each request and your IP address like any host does. Page views are counted with Cloudflare Web Analytics, which uses no cookies and no cross-site tracking. When enabled, Cloudflare adds a small beacon script from cloudflareinsights.com. There is no other analytics provider and no tracking code in the app.
Databases, CABBAGE snapshot and engines (this site or Zenodo)
The KMA and fastp engines ship with the page. The ResFinder, CARD and VFDB indexes and the CABBAGE snapshot are downloaded once from this site or from Zenodo and cached locally. Every file is checked against a pinned SHA-256 hash before it is used. A corrupted or altered download is rejected.
Fetching a public run (only when you ask)
If you fetch a run by accession or load the example, the accession and your IP address go to EMBL-EBI (ENA). ENA then knows which public run you fetched. The reads are cached in your browser like the databases.

That is all. To remove cached data (indexes, snapshot, example and fetched runs), use Clear cached data under the database selector on the main page.

Getting started

  1. Choose the input type: paired-end, single-end or Nanopore. Pick the databases to screen against. ResFinder is preselected, and any combination of ResFinder, CARD and VFDB runs in one go. Turn on fastp quality control if you want trimming and filtering, and open its settings to change the defaults.
  2. Select your read files (.fastq or .fastq.gz), or load the example: S. aureus USA300_TCH1516 (SRR10341524), a 48 MB MiSeq run of the community-associated MRSA reference strain, downloaded from ENA and cached in your browser. Expect mecA, blaZ, an aminoglycoside gene and a macrolide gene on ResFinder, and PVL and hla on VFDB. You can also fetch any public run by accession (SRR, ERR or DRR) with Fetch public run. The organism and read type are set from the ENA record. Files are limited to 1 GB each.
  3. Start the analysis. Progress is written to the Logs panel, which shows the exact KMA and fastp commands and their output.

CABBAGE: what the genes meant in other isolates

Gene detection tells you which genes are present. The Phenotype associations (CABBAGE) card adds what those genes meant in isolates that were tested in the laboratory. CABBAGE (Comprehensive Assessment of Bacterial-Based AMR prediction from Genotypes, Dickens et al., NAR 2026) links 170,750 sequenced isolates to 1.7 million susceptibility test results. Genotypes are AMRFinderPlus calls, and phenotypes are reinterpreted with the 2025 CLSI and EUCAST breakpoints.

openpathogen uses a snapshot of the portal, built by joining the genotype and phenotype tables on the isolate. For each species, gene and antibiotic it stores how many isolates carrying the gene tested resistant, intermediate or susceptible, and the same counts for all sequenced isolates of the species. Each detected resistance gene is matched to its CABBAGE symbol. The card then reads, for example: mecA, methicillin: 97.7% of 1,791 S. aureus carriers resistant, against 65% of all sequenced S. aureus.

Antibiotics that AMRFinderPlus links to the gene are listed first. Other antibiotics are listed as co-occurrence: the gene does not act on them, so those rates only show what else the same lineages carry. Only associations with at least 20 isolates are shown. Genes without CABBAGE data are listed as such. The species antibiogram below the associations shows resistance rates from all CABBAGE records and can be filtered by country, year and isolation source. Everything is computed in your browser from a cached snapshot, and the table is included in the results ZIP.

These are associations, not a susceptibility test. Confirm important results in the laboratory. To explore the full database, use the EMBL-EBI AMR portal.

Notes

  • The default thresholds are 90% template identity and 60% template coverage. Lower the identity threshold to pick up divergent variants, or lower the coverage threshold for fragmented or low-depth samples. Both sliders apply to every selected database.
  • Nanopore mode runs KMA with -bcNano for indel-aware base calling. fastp then only reports statistics.
  • Click any detected gene in the results to see its coverage, consensus sequence, alignment and variants.
  • The results ZIP contains, per database, .res, .aln, .fsa, .frag.gz, .mat.gz, .vcf.gz and .mapstat, plus the fastp reports, the CABBAGE table as CSV and the run log.
  • openpathogen needs a browser with SharedArrayBuffer support: recent Chrome, Firefox, Edge or Safari.
